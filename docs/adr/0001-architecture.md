# ADR-001: Архітектура навички wiki-interest-trends

**Статус:** прийнято · **Дата:** 2026-09-26 · **Вирішив:** Vitalii

## Контекст

Навичка допомагає B2C-фаундерам обирати теми і мови на основі переглядів Wikipedia. Вимоги кейсу:

- працює на дешевій моделі (Claude Haiku 4.5);
- ефективно обробляє повторні й пов'язані запити;
- робить припущення прозорими;
- середовище відтворюване;
- дедлайн — 2026-09-27.

Розглядали три варіанти: A — «чотири модулі-спеціалісти, агент-менеджер», B — «бланк дослідження + рушій», C — B, доповнений найкращими ідеями з A.

## Перевірка тверджень варіанта A на живих даних (2026-09-26)

| Твердження A | Що показала перевірка |
|---|---|
| SPARQL за `subclass of` / `part of` дає пов'язані теми (ML → Deep Learning, NLP; медитація → Mindfulness, Yoga) | Для ML — 69 елементів: chemometrics, linear regression, M-Theory… Для медитації — 41: zazen, Tonglen, Sufi whirling… Mindfulness і Yoga серед них немає |
| (альтернатива) | `morelike:` для «Meditation» у de дає Achtsamkeit (Geistesgegenwart) і Yoga; для «Астрономія» в uk — Астрофізика, Галактика, Всесвіт, а також шумний «Зодіак» |
| `analyze_controversy("Achtsamkeit", "de")` | «Achtsamkeit» у de — сторінка неоднозначності; справжня стаття — «Achtsamkeit (Geistesgegenwart)» |
| Індекс конфліктності з правок і відкатів | cs «Přerušovaný půst»: 0 правок за 90 днів. uk «Астрономія»: 6 правок, 4 з них відкати, тобто прибирання вандалізму, а не скептицизм |
| `pytrends` для Google Trends | Репозиторій архівовано (останні зміни — 2024-08). Офіційний API Google Trends з 2025-07 доступний лише в закритій альфі за заявками |
| WeasyPrint для PDF | Потребує системної бібліотеки Pango, через pip не встановлюється |
| statsmodels для сезонності | На 24 місячних точках кожен місяць року трапляється лише двічі; потрібно 4–5 років історії |

## Рішення

Обрано **варіант C**. Каркас B: агент заповнює бланк `study.json`, код робить решту. До нього додано дві ідеї з A у надійнішій реалізації:

1. **Сезонність** рахується за 5 років історії і має перевірку стабільності піку.
2. **Підказки суміжних тем** беруться через `morelike:` і мають номери Wikidata. Агент їх пропонує, а не додає мовчки.

Модулі «конфліктність» і «Google Trends» перенесено в план розвитку з умовами повернення.

## Компроміси

- **Свобода агента проти надійності на Haiku.** В A агент ухвалює рішення на кожному з 6–10 кроків. У C він ухвалює одне рішення (бланк) і пише висновок, решту робить детермінований код.
- **Кількість джерел проти їхньої якості.** Нестабільне або шумне джерело зменшує довіру до висновку, а не збільшує її.
- **Рамка «LLM — менеджер, скрипти — спеціалісти» збережена.** Менеджер оформлює одне замовлення замість шести окремих доручень.

## Наслідки

- **Стало легше:** проходити сценарії на Haiku, обробляти уточнення, пояснювати кожне число у звіті.
- **Стало складніше:** перший запуск довший, бо завантажується 5 років історії (далі працює кеш); підказки `morelike:` інколи шумні.
- **Переглянути пізніше:** модулі конфліктності й зовнішніх сигналів; SPARQL для масового групування тем (v3).
